# Profile contact verification

Profile > Edit profile saves validated name, residential address and zone to users/{uid}; Firebase UID and roles are unchanged. The existing address picker is reused. Demo mode blocks all writes. Current email/phone are not changed by this form's Save profile button.

Contact editing has separate six-digit OTP screens. Phone changes use Firebase PhoneAuthProvider + visible reCAPTCHA + updatePhoneNumber, followed by token refresh and syncing the authenticated phone into the profile. No signInWithPhoneNumber call is used, so changing a phone does not switch accounts. Current password or Google reauthentication is required before sending. In-flight edits are disabled; the verification is invalidated when the destination changes.

Email numeric OTP is NOT implemented on a server and is NOT active. The client contract expects asia-southeast1 requestProfileEmailOtp({email}) -> {challengeId} and confirmProfileEmailOtp({challengeId,code}). There is no email service or deployable backend in this Starter project yet. Do not enable VITE_PROFILE_EMAIL_OTP_ENABLED until real handlers have been implemented, reviewed, deployed and tested. Those handlers must enforce authentication and recent reauthentication, bind challenges to UID+target, generate cryptographically random codes, hash server-side, expire codes, limit attempts and delivery rates, consume codes atomically, never return/log codes, and update Firebase Authentication only after successful verification. Do not implement these checks only in the client.

Phone SMS also remains disabled by default. Configure Firebase Phone Authentication, authorized domains, SMS regions/quotas and applicable billing first, then set VITE_PROFILE_PHONE_OTP_ENABLED=true after an end-to-end test. Never commit test codes or credentials. Production email and phone updates must be tested with real reachable destinations before activation. No live Firebase settings, billing or credentials were changed.
